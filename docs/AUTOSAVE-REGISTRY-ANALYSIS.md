# یافته‌های تحلیل تنظیمات EMWAT و Registry

تاریخ: 2026-11-15  
منبع: artifact اجرای GitHub Actions با شناسه Run 117، فایل‌های disassembly و traceهای TD32 مربوط به `EmwatMethods.bpl1`  
روش: تحلیل ایستای باینری؛ بدون اجرای EMWAT و بدون دسترسی runtime به سامانه الماس.

## 1. مسیر تنظیمات تأییدشده در کد

در مسیر ذخیره تنظیمات فرم `TEmSettingForm`، رشته زیر به‌عنوان مسیر Registry استفاده می‌شود:

```text
Software\Emwat\Dynamic Config
```

کد این فرم شیء Registry را ایجاد می‌کند و hive برابر `0x80000001` را به آن می‌دهد که معادل `HKEY_CURRENT_USER` است. بنابراین مسیر تنظیمات این فرم:

```text
HKCU\Software\Emwat\Dynamic Config
```

است. این یافته مربوط به همین فرم و مسیر مشاهده‌شده است؛ هنوز ثابت نشده که تمام تنظیمات EMWAT فقط در همین کلید ذخیره می‌شوند.

## 2. نام مقادیر کشف‌شده

از رشته‌های Unicode و مسیر نوشتن تنظیمات در handler دکمه تأیید فرم، نام‌های زیر استخراج شدند:

| نام مقدار | برداشت مبتنی بر نام و کد | وضعیت |
|---|---|---|
| `Logging Level` | سطح جزئیات گزارش‌گیری | نام مقدار قطعی؛ دامنه مقادیر نامشخص |
| `Save I/O Trace Files` | فعال/غیرفعال‌کردن ذخیره traceهای I/O | نام مقدار قطعی؛ نوع دقیق داده هنوز نیازمند تأیید |
| `Background Priniting` | گزینه چاپ پس‌زمینه؛ املای ذخیره‌شده دقیقاً همین است | نام مقدار قطعی |
| `Dont Ask Save On Print` | کنترل پرسش ذخیره هنگام چاپ | نام مقدار قطعی |
| `Save Before Print` | کنترل ذخیره قبل از چاپ | نام مقدار قطعی |
| `AutoSaveInterval` | فاصله زمانی AutoSave | نام مقدار قطعی؛ واحد از کد استنباط شده |

## 3. رفتار AutoSaveInterval

در handler تأیید تنظیمات، مقدار انتخاب‌شده از کنترل فاصله AutoSave خوانده می‌شود.

رفتار مشاهده‌شده در disassembly:

- اگر مقدار انتخاب‌شده بزرگ‌تر از صفر و کوچک‌تر از 6 باشد، کد مقدار متناظر را از یک جدول lookup می‌خواند.
- مقدار جدول در 1000 ضرب می‌شود.
- نتیجه در Registry با نام `AutoSaveInterval` نوشته می‌شود.
- اگر مقدار انتخاب‌شده خارج از این بازه باشد، مقدار پیش‌فرض `10000` نوشته می‌شود.

بنابراین مقدار ذخیره‌شده به احتمال قوی بر حسب میلی‌ثانیه است؛ این برداشت از ضرب در 1000 و مقدار پیش‌فرض 10000 حاصل می‌شود. مقادیر واقعی جدول lookup هنوز در این trace استخراج نشده‌اند و نباید فاصله‌های دقیق گزینه‌های UI را حدس زد.

## 4. مسیر ذخیره تنظیمات

در handler تأیید فرم، کد به‌ترتیب مقدار چند کنترل را می‌خواند و آن‌ها را با نام‌های Registry بالا می‌نویسد. برای گزینه‌های عددی و بولی از مسیرهای helper متفاوت استفاده شده است. پس از نوشتن مقادیر، شیء Registry آزاد می‌شود.

این شواهد نشان می‌دهد این تنظیمات در سطح پروفایل کاربر نگهداری می‌شوند و در طراحی نسخه Linux بهتر است در پیکربندی per-user ذخیره شوند، نه در فایل تنظیمات سراسری سیستم.

## 5. پیامد برای Winux / EMWAT-Linux

برای نسخه Linux، یک لایه تنظیمات مستقل از Word و HTTP پیشنهاد می‌شود:

- محل پیکربندی per-user، مثلاً `$XDG_CONFIG_HOME/emwat-linux/config.toml`.
- حفظ نام‌های مفهومی گزینه‌ها، با نام‌گذاری تمیز و بدون وابستگی به املای اشتباه Registry.
- تبدیل واحد زمان به میلی‌ثانیه در مرز adapter، نه در منطق اصلی.
- مقدار پیش‌فرض AutoSave برابر 10000 میلی‌ثانیه فقط به‌عنوان رفتار مشاهده‌شده در این فرم؛ باید با چرخه واقعی AutoSave تطبیق داده شود.
- گزینه‌های Logging و I/O trace باید با کنترل حجم، حذف اطلاعات حساس و مجوزهای امن فایل پیاده شوند.

هیچ‌یک از این گزینه‌ها نباید به‌عنوان قرارداد HTTP یا پروتکل wire تلقی شوند.

## 6. محدودیت‌ها و کار بعدی

این تحلیل ایستا است. هنوز موارد زیر قطعی نشده‌اند:

1. مقادیر دقیق جدول فاصله‌های AutoSave در UI.
2. نوع Registry هر گزینه (DWORD، string یا نوع دیگر) در تمام مسیرهای خواندن و نوشتن.
3. اینکه این تنظیمات در شروع سرویس خوانده می‌شوند یا فقط هنگام ایجاد Word Viewer.
4. ارتباط دقیق AutoSave با `SilentSaveEmwatDoc` و ارسال پاسخ `EditWordDocument`.
5. اینکه AutoSaveInterval صفر یا مقدار پیش‌فرض چگونه بر timer واقعی اثر می‌گذارد.

گام بعدی باید اتصال readerهای Registry به فرم، Word Viewer و callback تایمر باشد؛ سپس مسیر AutoSave به ذخیره موقت سند و پاسخ connector متصل شود.
